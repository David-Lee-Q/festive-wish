### 用户指令条目

- Date: [YYYY-MM-DD]
- Context: [提及的场景或时间]
- Instructions:
  - [用户教导或指示的内容，逐行描述]

Agent 在任务执行过程中发现的条目应遵循以下格式：

[项目知识摘要]
- Date: [YYYY-MM-DD]
- Context: Agent 在执行 [具体任务描述] 时发现
- Category: [运维部署|构建方法|测试方法|排错调试|工作流协作|环境配置]

  - [具体的知识点，逐行描述]

## 去重策略
- 添加新条目前，检查是否存在相似或相同的指令
- 若发现重复，跳过新条目或与已有条目合并
- 合并时，更新上下文或日期信息
- 这有助于避免冗余条目，保持记忆文件整洁

## 条目

[重启服务时 stop.sh 与 start.sh 必须分两条命令执行]
- Date: 2026-09-22
- Context: Agent 在执行 职业/敬赠人字段开发 后重启服务时发现
- Category: 排错调试
- Instructions:
  - 本项目服务（端口 3000）的 stop.sh 和 start.sh 严禁用 && 串联在同一条 bash 命令里执行：bash 工具会等待 start.sh 派生的后台 node 进程，命令超时（约 90-120s）后被杀，连带把新启动的服务进程一起杀死，端口最终无人监听
  - 正确做法：先单独执行 `./stop.sh`（等其输出"端口 3000 已释放"），再单独执行 `./start.sh`（约 2 秒返回"服务启动成功"）
  - 判断是否踩坑的信号：命令链超时报错、`curl /api/health` 无响应、`ss -ltn` 显示端口空闲，但 server.log 可能仍打印过 running（进程已被杀）
  - 服务日志位于 /workspace/server.log，PID 记录在 /workspace/.server.pid
